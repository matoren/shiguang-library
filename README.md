# 拾光 · 私人书影音收藏馆

第一版 1.0.0 · 中文 · 安卓优先 · 本地保存 · 免费静态应用。

## 现在在 Windows 上打开

1. 双击 `start.cmd`，保持出现的窗口开启。当前电脑已有所需的 Node.js；其他电脑如未安装，窗口会提示安装官方 Node.js LTS。
2. 在浏览器打开 **http://127.0.0.1:4173/library/**。
3. 以后继续使用同一浏览器和同一个网址。不要直接双击 index.html，离线与数据库功能需要通过网页服务打开。
4. 结束使用后可以关闭启动窗口。已缓存的浏览器仍可离线使用；新浏览器首次打开需要重新启动窗口。

此地址仅用于当前电脑。安卓手机需要下方的正式 HTTPS 部署网址。`localhost` 与 `127.0.0.1` 属于不同存储来源，不要混用。

## 安卓安装：先完成一次 GitHub Pages 发布

独立仓库：https://github.com/matoren/shiguang-library 。应用访问地址为 https://matoren.github.io/shiguang-library/ ，首次发布需要等待 Pages 构建完成。应用本身不需要账号；所有收藏、评论和封面保存在当前浏览器的本地数据库，不上传 GitHub。

如需自行重新部署，可按以下步骤操作：

1. 在 GitHub 新建一个 **Public** 仓库，例如 `shiguang-library`。不要选择已有项目。
2. 解压交付包中的 `拾光-网页发布包.zip`。在新仓库选择 **Add file → Upload files**，把解压目录里的所有文件上传到仓库根目录；确保 `index.html` 直接位于根目录，然后提交。
3. 打开该仓库 **Settings → Pages**。Source 选择 **Deploy from a branch**，选择 `main` 和 `/(root)`，保存。
4. 等待 Pages 显示发布网址，再打开验证。网址通常是 `https://你的用户名.github.io/仓库名/`，以 GitHub 实际显示的为准。
5. 安卓 Chrome 打开该 HTTPS 网址，等待“离线缓存已就绪”，再从浏览器菜单选择“添加到主屏幕”或“安装应用”。首次加载需要联网。

流程依据：[GitHub Pages 官方部署说明](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)。GitHub Free 的 Pages 可使用公开仓库。只公开程序代码，收藏记录、封面和备份不应上传。

## 日常使用

- 首页点“记录一本书”或“记录一部电影”。名称必填，书籍需主分类。
- 选择封面可从相册或电脑上传。系统生成最长边不超过 1200 px 的封面和 360 px 缩略图，储存图片数据本身。再次编辑不重复压缩；重新选择图片时才处理。
- 六维书籍评分和四维电影评分使用下拉选择器，每次 0.5 分；“暂不评价”与 0 分不同。部分维度缺省时，按剩余权重归一化。
- 计算采用整数权重和整数十分位分数，使用十进制半入四舍五入，8.25 显示 8.3。最终分可每 0.1 分手动调整，保留计算结果。
- 电影可切换标准与快速模式，切换会确认，原模式的数据保留。
- 已读 / 已看作品进入完成统计；有有效最终分才参与平均分和排行榜。低于 7.0 显示 ✳，7.0 不标记。
- 书架与影库可搜索名称或创作者、筛选分类/标签/状态/出版或上映年份/评分区间，支持六种排序和列表视图。未评分作品评分排序时置后。
- 排行榜年份按完成日期筛选。首页“全部统计”可查看分类、评分区间及年度数量。

## 备份与恢复（请优先做这件事）

**设置 → 导出完整备份**，下载一个 JSON 文件，包括全部书籍、电影、评论、评分、规则快照、自定义权重、日期、设置和完整封面/缩略图。请确认下载成功，并把备份留在设备以外的安全位置。应用显示的是最近发起导出的时间，浏览器无法确认你是否保留了下载文件。

恢复时选择此文件：

- **合并导入**：保留现有设置；按唯一 ID 与“书名+作者+年份”或“电影名+年份”检测重复。重复会提示并跳过，绝不静默覆盖；如果确实要分别保留，先调整名称或年份。
- **覆盖恢复**：二次确认后，用备份替换当前全部记录和设置。建议先导出当前数据。

文件在导入前经过结构、评分、规则和图片解码校验。写入使用跨记录与设置的单次 IndexedDB 事务；校验错误或事务失败不会清空原有数据。第一版限制备份文件 300 MB、单图文件 30 MB、解码 6000 万像素，以减少内存耗尽风险。大量封面建议经常备份并在电脑恢复。

清除网站数据、设备故障、卸载以及浏览器存储回收仍可能导致数据丢失。可以在设置中申请持久存储，但它不能替代备份。手机与电脑、不同浏览器不会自动同步；用导出与导入手动迁移。

## 更新和历史数据

- 使用原仓库和原网址上传新的程序文件；不要更换来源。版本发布后在应用设置里“检查应用更新”，按提示确认并刷新。
- 发布前提升 `sw.js` 中缓存版本，每次完整发布所有静态文件。离线资源按版本整体缓存，新版本准备好后再由用户启用。
- Service Worker 只清理本应用的旧静态缓存，从不清理 IndexedDB。
- 每条作品保存评分模式、原始维度、权重快照、规则版本、计算分、最终分和手动状态。修改默认权重只影响新增记录；批量应用已有书籍需要另行确认，保留手动最终分。
- 数据库初始结构 v1，只在首次安装时创建缺失表。未来升级必须增加显式的增量迁移和测试；不会通过删除数据库“升级”。备份当前只接受 v1，未知版本会拒绝恢复，而不是猜测格式。
- 变更域名、仓库路径或浏览器前，先导出备份，再到新来源导入。

## 开发与复核

无需安装 npm 依赖。`npm start` 启动本地服务；`npm test` 执行 20 项核心测试。浏览器打开 `/library/tests/browser.html` 可运行 11 项真实 IndexedDB 集成测试，仅使用独立测试数据库。`/library/tests/mobile.html` 提供手机框架布局检查。

目录中的 `.github/workflows/checks.yml` 可用于源代码仓库自动测试。网页发布包仅含运行所需文件，不含个人备份、测试记录或任何数据库。

完整测试结果与限制见交付目录的《测试与交付说明.md》。安卓真机安装、相册选择、操作系统回收后的重开，以及正式 Pages HTTPS 地址需要在发布后验收。
